客户端接口文档
================

一、通讯基础说明
----------------
*   **传输协议**：TCP（服务器监听 IPv6 通配地址，端口 `8080`）
*   **数据编码**：二进制帧结构（详见第二节「帧格式」），帧体内部为 UTF-8 编码的标准 JSON 字符串。
*   **关键特点**：
    1.  **支持粘包/半包处理**：服务器采用「4 字节总长度 + 4 字节 JSON 长度」的定长包头进行分包解析。客户端发送数据时**无需**添加换行符 `\n`，但必须正确填写帧头长度字段。
    2.  **基于 UID 寻址**：所有用户（个人）和群组均以整数 UID 作为唯一标识。登录、私聊、群聊操作均使用 UID，而非用户名。
    3.  **服务器主动推送**：服务器可随时主动向客户端推送消息（如对方私聊、系统通知），客户端应**开启独立的接收线程**循环读取并解析帧。

二、帧格式（二进制协议）
------------------------
所有通信数据均封装为如下帧结构：
```
┌──────────────┬──────────────┬──────────────┬──────────────┐
│  4 字节       │  4 字节       │ JSON 字符串   │ 文件数据(可选)│
│  总长度 total │ JSON 长度 json│  (明文)       │  (file_data) │
└──────────────┴──────────────┴──────────────┴──────────────┘
```
*   **总长度 (total_len)**：`uint32_t`，主机序转网络序（`htonl`）。其值 = `8 + json字符串字节数 + 文件数据字节数`。
*   **JSON 长度 (json_len)**：`uint32_t`，主机序转网络序（`htonl`）。其值 = JSON 字符串的字节长度。
*   **JSON 部分**：紧跟在两个 4 字节长度字段之后，长度为 `json_len`。
*   **文件数据部分**：紧跟在 JSON 之后，长度为 `total_len - 4 - json_len`，可缺省（长度为 0）。

> 服务器解析时，先读取前 4 字节得到 `total_len`，若接收缓冲区不足 `4 + total_len` 则等待更多数据（半包）；处理完当前帧后继续循环处理剩余数据（粘包）。

三、消息类型总览
----------------
客户端发送的每一帧，其 JSON 部分必须包含 `"type"` 字段，用于指示消息类型。以下是全部受支持的类型：

| type                  | 归类     | 说明                                   |
|-----------------------|----------|----------------------------------------|
| `register`            | 基础     | 注册新账号                             |
| `login`               | 基础     | 用户登录                               |
| `logout`              | 基础     | 登出当前账号（保留连接，可再登录）     |
| `show`                | 基础     | 展示聊天对象列表（好友 + 群组）        |
| `change_name`         | 基础     | 修改自己的昵称                         |
| `exit`                | 基础     | 退出系统、关闭连接                     |
| `heartbeat`           | 基础     | 心跳包（无业务消息时的保活）           |
| `private_chat`        | 私聊     | 私聊（一对一向指定 UID 发消息）        |
| `group_chat`          | 群聊     | 群聊发言（向指定群 UID 广播）           |
| `add_friend`          | 好友     | 发送好友申请（存于 `relation_apply`，apply_type=1） |
| `set_friend_remark`   | 好友     | 给好友设置备注名                       |
| `accept_friend`       | 好友     | 同意好友申请                           |
| `reject_friend`       | 好友     | 拒绝好友申请                           |
| `remove_friend`       | 好友     | 删除好友                               |
| `show_friend_requests`| 好友     | 查看待处理的好友申请                   |
| `create_group`        | 群组     | 创建群聊                               |
| `delete_group`        | 群组     | 解散群聊                               |
| `group_add_client`    | 群组     | 添加群成员                             |
| `group_delete_client` | 群组     | 移除群成员（踢人）                     |
| `modify_group_name`   | 群组     | 修改群名称                             |
| `send_join_group`     | 群组     | 申请加入群聊（落库申请，等待群主处理） |
| `handle_join_request` | 群组     | 处理入群申请（同意/拒绝）              |
| `modify_member_role`  | 群组     | 修改群成员身份（提升/降级）            |
| `show_group_members`  | 群组     | 查看群成员（含群内名字）               |
| `upload_file`         | 文件     | 上传文件（分块）                       |
| `download_file`       | 文件     | 下载文件                               |

四、客户端请求接口（Client -> Server）
--------------------------------------
以下所有请求的 JSON 字段名必须与描述严格一致，类型不可混淆。

### 1. 注册账号 (register)
*   **用途**：创建新账号。服务器自动分配 UID。
*   **JSON 结构**：
```json
{
    "type": "register",
    "username": "张三",
    "password": "123456"
}
```
*   *注意*：注册成功后服务器会在返回的 `system` 消息中回传分配到的 UID，例如 `Registration successful. You can now log in with UID 000001.`，请解析 content 获取 UID 用于后续登录。

### 2. 用户登录 (login)
*   **用途**：使用 UID + 密码登录。连接建立后客户端应在收到登录成功之前等待。
*   **JSON 结构**：
```json
{
    "type": "login",
    "UID": 1001,
    "password": "123456"
}
```
*   *注意*：字段为 **UID**（整数），**不是** username。登录成功后服务器会把该连接的会话标识从 socket fd 切换为 UID。

### 3. 展示聊天列表 (show)
*   **用途**：返回当前登录用户的好友列表与已加入的群组列表。
*   **JSON 结构**：
```json
{
    "type": "show"
}
```

### 4. 私聊 (private_chat)
*   **用途**：向指定目标用户 UID 发送私有消息。
*   **JSON 结构**：
```json
{
    "type": "private_chat",
    "target_UID": 1002,
    "message": "你好呀！"
}
```
*   *注意*：服务器会校验目标 UID 是否存在及是否在线，收到后以 `[发送者名字]: 内容` 的格式转发给目标。

### 5. 群聊 (group_chat)
*   **用途**：向指定群发消息，群内所有在线成员会收到以 `Group_Chat` 类型转发的消息。
*   **JSON 结构**：
```json
{
    "type": "group_chat",
    "target_UID": 2001,
    "message": "大家好！"
}
```

### 6. 创建群聊 (create_group)
*   **用途**：新建群，创建者自动成为群主（管理员），并加入自己的好友/群组列表。
*   **JSON 结构**：
```json
{
    "type": "create_group",
    "group_name": "我的新群聊"
}
```
*   *注意*：创建成功后服务器会在返回的 `system` 消息中回传新建群的 UID，例如 `Group created successfully. Group name: [我的新群聊], Group UID: 002001.`，请解析 content 获取群 UID，后续加人/发言/改名都使用该 UID。

### 7. 解散群聊 (delete_group)
*   **用途**：群主解散指定群。
*   **JSON 结构**：
```json
{
    "type": "delete_group",
    "group_UID": 2001
}
```

### 8. 添加群成员 (group_add_client)
*   **用途**：群主向群内添加成员。
*   **JSON 结构**：
```json
{
    "type": "group_add_client",
    "group_UID": 2001,
    "target_user_UID": 1003
}
```

### 9. 移除群成员 (group_delete_client)
*   **用途**：群主踢出指定成员。
*   **JSON 结构**：
```json
{
    "type": "group_delete_client",
    "group_UID": 2001,
    "target_user_UID": 1003
}
```

### 10. 修改群名称 (modify_group_name)
*   **用途**：群主修改群名称。
*   **JSON 结构**：
```json
{
    "type": "modify_group_name",
    "group_UID": 2001,
    "new_name": "新群名"
}
```

### 11. 上传文件 (upload_file)
*   **用途**：发送方传输文件块（分块上传，单块最大 256KB）。文件数据放在帧的「文件数据部分」，JSON 中携带分块元信息。
*   **JSON 结构（元信息）**：
```json
{
    "type": "upload_file",
    "meta": {
        "file_id": "1000000000",
        "filename": "report.pdf",
        "total_size": 700000,
        "chunk_index": 0,
        "chunk_count": 3,
        "chunk_size": 262144,
        "offset": 0
    },
    "file_data": "……本块文件二进制数据……"
}
```
*   **meta 字段说明**：
    *   `file_id`：本次传输的唯一标识（服务器用时间戳生成）。
    *   `filename`：原始文件名。
    *   `total_size`：文件总大小（字节）。
    *   `chunk_index`：当前块下标（从 0 开始）。
    *   `chunk_count`：总块数。
    *   `chunk_size`：当前块的实际字节数。
    *   `offset`：当前块在文件中的起始偏移。
*   *注意*：`meta` 为 JSON 对象，二进制文件数据通过帧尾部的文件数据段传递，不放入 JSON 内。

### 12. 下载文件 (download_file)
*   **用途**：请求服务器发送指定文件。服务器响应以 `file_chunk` 类型分块推送。
*   **JSON 结构**：
```json
{
    "type": "download_file",
    "file_name": "report.pdf"
}
```
*   *注意*：服务器会在 `saving_path`（`./received_files/`）目录下查找该文件名。

### 13. 安全退出 (exit)
*   **用途**：告知服务器下线，清理资源并关闭连接。
*   **JSON 结构**：
```json
{
    "type": "exit"
}
```

### 14. 登出账号 (logout)
*   **用途**：退出当前账号登录，但**保持连接**（与 `exit` 的彻底断开不同）。登出后该连接仍可继续登录其他账号或接收系统消息。
*   **JSON 结构**：
```json
{
    "type": "logout"
}
```
*   *注意*：服务器返回 `Logout successful.` 提示，并清空当前会话的账号与社交状态；连接本身不断开。

### 15. 心跳包 (heartbeat) *（可选/可配）*
*   **用途**：在无业务消息时维持连接活跃，避免被服务器判定为超时断开。由客户端按固定周期（如每 30 秒）发送。
*   **JSON 结构**：
```json
{
    "type": "heartbeat"
}
```
*   *注意*：该功能是否启用、超时阈值（默认 60 秒）由服务器配置 `configure.json` 中的 `use_heartbeat` / `heartbeat_interval` 决定，默认关闭。启用后客户端需周期发送心跳；服务器收到心跳会回 `heartbeat_ack`。若一段时间内既无业务消息也无心跳，服务器会主动断开该连接。

### 16. 设置好友备注名 (set_friend_remark)
*   **用途**：给指定好友 UID 设置备注名（存于 `friend_relation.remark_name`）。
*   **JSON 结构**：
```json
{
    "type": "set_friend_remark",
    "friend_UID": 1002,
    "remark": "老张"
}
```
*   *注意*：服务器会校验目标 UID 是否为当前登录用户的好友；不是好友或备注名为空时返回失败提示。

### 17. 修改自己的昵称 (change_name)
*   **用途**：修改当前登录账号的昵称（存于 `Account.nickname`）。
*   **JSON 结构**：
```json
{
    "type": "change_name",
    "new_name": "新昵称"
}
```
*   *注意*：昵称全局唯一（`uk_nickname`），新昵称为空或与现有用户重名时返回失败提示；成功后返回包含新昵称的系统提示。

### 18. 发送好友申请 (add_friend)
*   **用途**：向指定 UID 发送好友申请（存于 `relation_apply`，apply_type=1，status=0 等待）。
*   **JSON 结构**：
```json
{
    "type": "add_friend",
    "target_UID": 1002,
    "apply_message": "我是张三"
}
```
*   *注意*：若同对用户已存在等待中的申请，会返回失败提示（由唯一约束拦截）。

### 19. 查看待处理的好友申请 (show_friend_requests)
*   **用途**：列出发给当前用户、等待处理（status=0）的好友申请。
*   **JSON 结构**：
```json
{
    "type": "show_friend_requests"
}
```

### 20. 同意好友申请 (accept_friend)
*   **用途**：同意来自 `sender_UID` 的好友申请，双方成为好友（事务内双向落库）。
*   **JSON 结构**：
```json
{
    "type": "accept_friend",
    "sender_UID": 1001
}
```

### 21. 拒绝好友申请 (reject_friend)
*   **用途**：拒绝来自 `sender_UID` 的好友申请。
*   **JSON 结构**：
```json
{
    "type": "reject_friend",
    "sender_UID": 1001
}
```

### 22. 删除好友 (remove_friend)
*   **用途**：删除指定好友（事务内双向删除 `friend_relation`）。
*   **JSON 结构**：
```json
{
    "type": "remove_friend",
    "friend_UID": 1002
}
```

### 23. 申请加入群聊 (send_join_group)
*   **用途**：向指定群发送入群申请。服务器落库一条申请（`relation_apply`，apply_type=2，status=0 等待），由群主调用 `handle_join_request` 处理。
*   **JSON 结构**：
```json
{
    "type": "send_join_group",
    "group_UID": 2001
}
```
*   *注意*：群不存在、已是群成员、或同人同群已有等待中的申请时返回失败提示。

### 24. 处理入群申请 (handle_join_request)
*   **用途**：群主处理某用户的入群申请。同意后该用户被拉入群（群内名字默认取其用户昵称），拒绝则仅更新申请状态。
*   **JSON 结构**：
```json
{
    "type": "handle_join_request",
    "group_UID": 2001,
    "requester_UID": 1003,
    "accept": true
}
```
*   *注意*：`requester_UID` 为申请人（待处理者），`accept` 为布尔值（true 同意 / false 拒绝）。只有群主能处理。

### 25. 修改群成员身份 (modify_member_role)
*   **用途**：群主提升/降级群成员身份。
*   **JSON 结构**：
```json
{
    "type": "modify_member_role",
    "group_UID": 2001,
    "target_UID": 1003,
    "promote": true
}
```
*   *注意*：`promote` 为布尔值（true 提升为 owner / false 降回 member）。只有群主能操作。

### 26. 查看群成员 (show_group_members)
*   **用途**：查看指定群的全部成员，返回每行一条 `UID: 群内名字`。
*   **JSON 结构**：
```json
{
    "type": "show_group_members",
    "group_UID": 2001
}
```

五、服务器返回格式（Server -> Client）
--------------------------------------
服务器返回的数据同样封装为二进制帧结构。其 JSON 部分包含 `type` 和 `content` 字段：
```json
{
    "type": "system",
    "content": "……纯文本内容……"
}
```

| 响应类型 (type)       | 场景/含义                                            | content 内容示例                                        |
|-----------------------|------------------------------------------------------|--------------------------------------------------------|
| `system`              | 通用系统提示、登录/注册结果、错误提示等              | `Login successful. Welcome, 张三!` 等                  |
| `private_chat`        | 收到私聊消息                                         | `[张三]: 你好呀！`                                     |
| `Group_Chat`          | 收到群聊消息（注意大小写 `Group_Chat`）              | 群内消息内容                                            |
| `file_chunk`          | 服务器发送文件块（下载响应）                         | JSON 中包含 `file_id/filename/total_size/chunk_index/...` 元信息，文件数据在帧尾 |
| `heartbeat_ack`       | 服务器对心跳包的应答（`content` 为 `pong`）          | `pong`                                                  |

| 触发场景                 | content 内容（示例）                                          |
|--------------------------|---------------------------------------------------------------|

六、聊天列表返回格式（show）
----------------------------
`show` 请求的返回同样以 `system` 类型、`content` 纯文本形式返回。格式为**每行一条记录**，行内格式为 `名称:UID`：
*   好友记录：`<用户名>:<6位补齐的UID>`，例如 `张三:001001`
*   群组记录：`<群名>:<6位补齐的UID>`，例如 `我的新群聊:002001`

示例：
```
张三:001001
李四:001002
我的新群聊:002001
```

七、完整交互流程示例
--------------------
1.  **建立连接**：客户端连接服务器 `:8080`。
2.  **登录**：发送 `{"type":"login","UID":1001,"password":"123456"}`，收到 `Login successful...` 后视为登录成功。
3.  **查询列表**：发送 `{"type":"show"}`，解析返回文本得到好友/群组及对应 UID。
4.  **私聊**：发送 `{"type":"private_chat","target_UID":1002,"message":"你好"}`。
5.  **接收**：接收线程持续解析帧，当 `type` 为 `private_chat` / `Group_Chat` / `system` 时分别处理。
6.  **退出**：发送 `{"type":"exit"}` 后断开连接。

八、客户端开发建议
------------------
1.  **独立接收线程**：服务器支持主动推送，客户端必须开启独立线程持续 `recv` 并调用帧解析逻辑（参照服务器 `receiver::process_recv_data` 的实现，用 `in_buffer` + 循环解析处理粘包/半包）。
2.  **严格遵循帧头**：发送前务必计算 `total_len = 8 + json字节数 + file字节数` 与 `json_len`，并以网络字节序（大端）写入前 8 字节。
3.  **登录状态控制**：在收到 `Login successful` 之前，除了 `login`（必要时 `register`）请求，不要发送其它业务请求。
4.  **UID 而非用户名**：所有寻址均使用整数 UID，注意与历史版本（使用 `username`/`target_name` 的旧版）区分。
5.  **文件分块**：上传/下载均基于 256KB 分块与 `file_id` 标识，客户端需自行按块组装文件并处理断点续传（当前为一次性分块传输）。

九、附加：服务端部署与配置（供运维/联调参考）
-----------------------------------------------
以上接口与客户端开发无关，但联调前请确认服务端配置有效：
- 服务端启动时读取**相对路径** `configure.json`，需先复制到运行目录再启动（如 `cp configure.json build/`）。
- `configure.json` 含两部分：
    1. 心跳：`use_heartbeat`（开关）、`heartbeat_interval`（超时秒数）。
    2. 数据库连接池：`database` 下的 `host/port/user/password/dbname/db_conn_count`
       （`db_conn_count` 为连接池上限，默认 4）。
- 未读到配置文件时会使用默认值（见 readme.md / 数据库设计.txt），可能导致无法连接你的数据库。
