客户端接口文档
================

一、通讯基础说明
----------------
*   **传输协议**：TCP（服务器监听 IPv6 通配地址，端口 `8080`）
*   **数据编码**：二进制帧结构（详见第二节「帧格式」），帧体内部为 UTF-8 编码的标准 JSON 字符串。
*   **关键特点**：
    1.  **支持粘包/半包处理**：服务器采用「4 字节总长度 + 4 字节 JSON 长度」的定长包头进行分包解析。客户端发送数据时**无需**添加换行符 `\n`，但必须正确填写帧头长度字段。
    2.  **基于 UID 寻址**：所有用户（个人）和群组均以整数 UID 作为唯一标识。登录、私聊、群聊操作均使用 UID，而非用户名。
    3.  **服务器主动推送**：服务器可随时主动向客户端推送消息（如对方私聊、系统通知），客户端应**开启独立的接收线程**循环读取并解析帧。

二、帧格式（二进制协议）
------------------------
所有通信数据均封装为如下帧结构：
```
┌──────────────┬──────────────┬──────────────┬──────────────┐
│  4 字节       │  4 字节       │ JSON 字符串   │ 文件数据(可选)│
│  总长度 total │ JSON 长度 json│  (明文)       │  (file_data) │
└──────────────┴──────────────┴──────────────┴──────────────┘
```
*   **总长度 (total_len)**：`uint32_t`，主机序转网络序（`htonl`）。其值 = `8 + json字符串字节数 + 文件数据字节数`。
*   **JSON 长度 (json_len)**：`uint32_t`，主机序转网络序（`htonl`）。其值 = JSON 字符串的字节长度。
*   **JSON 部分**：紧跟在两个 4 字节长度字段之后，长度为 `json_len`。
*   **文件数据部分**：紧跟在 JSON 之后，长度为 `total_len - 4 - json_len`，可缺省（长度为 0）。

> 服务器解析时，先读取前 4 字节得到 `total_len`，若接收缓冲区不足 `4 + total_len` 则等待更多数据（半包）；处理完当前帧后继续循环处理剩余数据（粘包）。

三、消息类型总览
----------------
客户端发送的每一帧，其 JSON 部分必须包含 `"type"` 字段，用于指示消息类型。以下是全部受支持的类型：

| type                  | 归类     | 说明                                   |
|-----------------------|----------|----------------------------------------|
| `register`            | 基础     | 注册新账号                             |
| `login`               | 基础     | 用户登录                               |
| `show`                | 基础     | 展示聊天对象列表（好友 + 群组）        |
| `exit`                | 基础     | 退出系统、关闭连接                     |
| `private_chat`        | 私聊     | 私聊（一对一向指定 UID 发消息）        |
| `group_chat`          | 群聊     | 群聊发言（向指定群 UID 广播）           |
| `create_group`        | 群组     | 创建群聊                               |
| `delete_group`        | 群组     | 解散群聊                               |
| `group_add_client`    | 群组     | 添加群成员                             |
| `group_delete_client` | 群组     | 移除群成员（踢人）                     |
| `modify_group_name`   | 群组     | 修改群名称                             |
| `upload_file`         | 文件     | 上传文件（分块）                       |
| `download_file`       | 文件     | 下载文件                               |

四、客户端请求接口（Client -> Server）
--------------------------------------
以下所有请求的 JSON 字段名必须与描述严格一致，类型不可混淆。

### 1. 注册账号 (register)
*   **用途**：创建新账号。服务器自动分配 UID。
*   **JSON 结构**：
```json
{
    "type": "register",
    "username": "张三",
    "password": "123456"
}
```
*   *注意*：注册成功后服务器会在返回的 `system` 消息中回传分配到的 UID，例如 `Registration successful. You can now log in with UID 000001.`，请解析 content 获取 UID 用于后续登录。

### 2. 用户登录 (login)
*   **用途**：使用 UID + 密码登录。连接建立后客户端应在收到登录成功之前等待。
*   **JSON 结构**：
```json
{
    "type": "login",
    "UID": 1001,
    "password": "123456"
}
```
*   *注意*：字段为 **UID**（整数），**不是** username。登录成功后服务器会把该连接的会话标识从 socket fd 切换为 UID。

### 3. 展示聊天列表 (show)
*   **用途**：返回当前登录用户的好友列表与已加入的群组列表。
*   **JSON 结构**：
```json
{
    "type": "show"
}
```

### 4. 私聊 (private_chat)
*   **用途**：向指定目标用户 UID 发送私有消息。
*   **JSON 结构**：
```json
{
    "type": "private_chat",
    "target_UID": 1002,
    "message": "你好呀！"
}
```
*   *注意*：服务器会校验目标 UID 是否存在及是否在线，收到后以 `[发送者名字]: 内容` 的格式转发给目标。

### 5. 群聊 (group_chat)
*   **用途**：向指定群发消息，群内所有在线成员会收到以 `Group_Chat` 类型转发的消息。
*   **JSON 结构**：
```json
{
    "type": "group_chat",
    "target_UID": 2001,
    "message": "大家好！"
}
```

### 6. 创建群聊 (create_group)
*   **用途**：新建群，创建者自动成为群主（管理员），并加入自己的好友/群组列表。
*   **JSON 结构**：
```json
{
    "type": "create_group",
    "group_name": "我的新群聊"
}
```
*   *注意*：创建成功后服务器会在返回的 `system` 消息中回传新建群的 UID，例如 `Group created successfully. Group name: [我的新群聊], Group UID: 002001.`，请解析 content 获取群 UID，后续加人/发言/改名都使用该 UID。

### 7. 解散群聊 (delete_group)
*   **用途**：群主解散指定群。
*   **JSON 结构**：
```json
{
    "type": "delete_group",
    "group_UID": 2001
}
```

### 8. 添加群成员 (group_add_client)
*   **用途**：群主向群内添加成员。
*   **JSON 结构**：
```json
{
    "type": "group_add_client",
    "group_UID": 2001,
    "target_user_UID": 1003
}
```

### 9. 移除群成员 (group_delete_client)
*   **用途**：群主踢出指定成员。
*   **JSON 结构**：
```json
{
    "type": "group_delete_client",
    "group_UID": 2001,
    "target_user_UID": 1003
}
```

### 10. 修改群名称 (modify_group_name)
*   **用途**：群主修改群名称。
*   **JSON 结构**：
```json
{
    "type": "modify_group_name",
    "group_UID": 2001,
    "new_name": "新群名"
}
```

### 11. 上传文件 (upload_file)
*   **用途**：发送方传输文件块（分块上传，单块最大 256KB）。文件数据放在帧的「文件数据部分」，JSON 中携带分块元信息。
*   **JSON 结构（元信息）**：
```json
{
    "type": "upload_file",
    "meta": {
        "file_id": "1000000000",
        "filename": "report.pdf",
        "total_size": 700000,
        "chunk_index": 0,
        "chunk_count": 3,
        "chunk_size": 262144,
        "offset": 0
    },
    "file_data": "……本块文件二进制数据……"
}
```
*   **meta 字段说明**：
    *   `file_id`：本次传输的唯一标识（服务器用时间戳生成）。
    *   `filename`：原始文件名。
    *   `total_size`：文件总大小（字节）。
    *   `chunk_index`：当前块下标（从 0 开始）。
    *   `chunk_count`：总块数。
    *   `chunk_size`：当前块的实际字节数。
    *   `offset`：当前块在文件中的起始偏移。
*   *注意*：`meta` 为 JSON 对象，二进制文件数据通过帧尾部的文件数据段传递，不放入 JSON 内。

### 12. 下载文件 (download_file)
*   **用途**：请求服务器发送指定文件。服务器响应以 `file_chunk` 类型分块推送。
*   **JSON 结构**：
```json
{
    "type": "download_file",
    "file_name": "report.pdf"
}
```
*   *注意*：服务器会在 `saving_path`（`./received_files/`）目录下查找该文件名。

### 13. 安全退出 (exit)
*   **用途**：告知服务器下线，清理资源并关闭连接。
*   **JSON 结构**：
```json
{
    "type": "exit"
}
```

五、服务器返回格式（Server -> Client）
--------------------------------------
服务器返回的数据同样封装为二进制帧结构。其 JSON 部分包含 `type` 和 `content` 字段：
```json
{
    "type": "system",
    "content": "……纯文本内容……"
}
```

| 响应类型 (type)       | 场景/含义                                            | content 内容示例                                        |
|-----------------------|------------------------------------------------------|--------------------------------------------------------|
| `system`              | 通用系统提示、登录/注册结果、错误提示等              | `Login successful. Welcome, 张三!` 等                  |
| `private_chat`        | 收到私聊消息                                         | `[张三]: 你好呀！`                                     |
| `Group_Chat`          | 收到群聊消息（注意大小写 `Group_Chat`）              | 群内消息内容                                            |
| `file_chunk`          | 服务器发送文件块（下载响应）                         | JSON 中包含 `file_id/filename/total_size/chunk_index/...` 元信息，文件数据在帧尾 |

### 常见系统提示文本
| 触发场景                 | content 内容（示例）                                          |
|--------------------------|---------------------------------------------------------------|
| **注册成功**             | `Registration successful. You can now log in with UID 000001.`  |
| **用户名或密码为空**     | `Username and password cannot be empty.`                      |
| **登录成功**             | `Login successful. Welcome, <用户名>!`                        |
| **UID 不存在**           | `Account with UID [<UID>] does not exist.`                    |
| **密码错误**             | `Incorrect password for UID [<UID>].`                         |
| **退出系统**             | `Goodbye!`                                                    |
| **创建群成功**           | `Group created successfully. Group name: [<群名>], Group UID: <群UID>.` |
| **消息为空**（私聊）     | `Message cannot be empty.`                                    |
| **未登录发私聊**         | `You must be logged in to send private messages.`             |
| **目标 UID 不存在**      | `UID [<UID>] does not exist.`                                 |
| **目标不在线**           | `User [<UID>] is not online.`                                 |
| **群名称为空**           | `The group name can't be empty`                               |
| **修改群名无权限**       | `Permission denied: only manager can modify group name.`      |
| **缺少 type 字段**       | `Invalid message format: missing 'type' field.`               |
| **未知命令类型**         | `Unknown command type.`                                       |

六、聊天列表返回格式（show）
----------------------------
`show` 请求的返回同样以 `system` 类型、`content` 纯文本形式返回。格式为**每行一条记录**，行内格式为 `名称:UID`：
*   好友记录：`<用户名>:<6位补齐的UID>`，例如 `张三:001001`
*   群组记录：`<群名>:<6位补齐的UID>`，例如 `我的新群聊:002001`

示例：
```
张三:001001
李四:001002
我的新群聊:002001
```

七、完整交互流程示例
--------------------
1.  **建立连接**：客户端连接服务器 `:8080`。
2.  **登录**：发送 `{"type":"login","UID":1001,"password":"123456"}`，收到 `Login successful...` 后视为登录成功。
3.  **查询列表**：发送 `{"type":"show"}`，解析返回文本得到好友/群组及对应 UID。
4.  **私聊**：发送 `{"type":"private_chat","target_UID":1002,"message":"你好"}`。
5.  **接收**：接收线程持续解析帧，当 `type` 为 `private_chat` / `Group_Chat` / `system` 时分别处理。
6.  **退出**：发送 `{"type":"exit"}` 后断开连接。

八、客户端开发建议
------------------
1.  **独立接收线程**：服务器支持主动推送，客户端必须开启独立线程持续 `recv` 并调用帧解析逻辑（参照服务器 `receiver::process_recv_data` 的实现，用 `in_buffer` + 循环解析处理粘包/半包）。
2.  **严格遵循帧头**：发送前务必计算 `total_len = 8 + json字节数 + file字节数` 与 `json_len`，并以网络字节序（大端）写入前 8 字节。
3.  **登录状态控制**：在收到 `Login successful` 之前，除了 `login`（必要时 `register`）请求，不要发送其它业务请求。
4.  **UID 而非用户名**：所有寻址均使用整数 UID，注意与历史版本（使用 `username`/`target_name` 的旧版）区分。
5.  **文件分块**：上传/下载均基于 256KB 分块与 `file_id` 标识，客户端需自行按块组装文件并处理断点续传（当前为一次性分块传输）。
