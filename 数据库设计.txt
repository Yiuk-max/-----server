数据库设计（对应 sql/create_table.sql，与线上 chat_server 库结构一致）
数据库：MySQL 8.0（当前库 collate 为 utf8mb4_0900_ai_ci）
字符集：utf8mb4（必须，否则中文/emoji 会乱码或插入失败）
本项目数据库专用账户，name: chat_server,password:Chat_123!

============================================================
1. Account 表（用户账户）
------------------------------------------------------------
| 字段        | 类型             | 说明                         |
| UID         | bigint unsigned | 主键，系统自增分配            |
| password    | varchar(128)    | 密码（建议存 hash）           |
| nickname    | varchar(64)     | 昵称（允许重复）             |
| settings    | json            | 可空，账号设置(主题/语言/通知开关)|
| language    | varchar(16)     | 默认 'Chinese'               |
| create_time | datetime        | 默认 CURRENT_TIMESTAMP       |
| birthday    | date            | 可空                          |
------------------------------------------------------------
主键 UID
外键：无

说明：
- nickname 不再唯一：登录/加好友/发消息均按 UID 定位，昵称、密码都允许重复
- 旧库需执行 sql/allow_duplicate_nickname.sql（ALTER TABLE Account DROP INDEX uk_nickname）
- settings 为 JSON 列（承载 account.h 中的账号设置字段，应用层序列化）
- birthday 允许 NULL

============================================================
2. friend_relation 表（好友关系，双向同步）
------------------------------------------------------------
| 字段        | 类型             | 说明                         |
| UID         | bigint unsigned | 用户A（主键1）                |
| friend_UID  | bigint unsigned | 好友B（主键2）                |
| remark_name | varchar(64)     | 备注名，可空                  |
| create_time | datetime        | 默认 CURRENT_TIMESTAMP       |
------------------------------------------------------------
联合主键 (UID, friend_UID)
外键：fk_fr_uid(UID->Account.UID)，fk_fr_friend(friend_UID->Account.UID)，
      均 ON DELETE CASCADE

双向同步设计：
- 逻辑上 A、B 互为好友后需存 (A,B) 与 (B,A) 两行
- 由 repo 应用层在【事务内双写】保证一致性（不使用 DB 触发器，
  因 DELIMITER 语法无法在 JDBC/Connector 逐条执行）
- 查询任一方好友列表只需 WHERE UID=? 即可，无需双向判断
- 删除好友同样在事务内删两行；删除账户时外键 CASCADE 自动清理两端

DB 事务双写参考：
    START TRANSACTION;
    INSERT INTO friend_relation (UID, friend_UID, remark_name) VALUES (:A,:B,:r);
    INSERT INTO friend_relation (UID, friend_UID, remark_name) VALUES (:B,:A,:r);
    COMMIT;

============================================================
3. relation_apply 表（关系申请表，原 friend_request 更名扩展）
------------------------------------------------------------
| 字段         | 类型            | 说明                         |
| id           | int unsigned   | 自增主键                     |
| apply_type   | tinyint        | 申请类型: 1=好友申请 2=群聊申请|
| sender_UID   | bigint unsigned| 申请人                       |
| receiver_UID | bigint unsigned| 接收方(好友=对方;群聊=群主/管理员)|
| group_UID    | bigint unsigned| 群聊申请的目标群(好友申请为0)  |
| message      | varchar(255)   | 申请附加留言，可空             |
| status       | tinyint        | 0等待 1同意 2拒绝             |
| create_time  | datetime       | 默认 CURRENT_TIMESTAMP       |
------------------------------------------------------------
主键 id
唯一键 uk_apply(apply_type, sender_UID, receiver_UID, group_UID, status)
外键：fk_ra_sender(sender_UID->Account.UID)，
      fk_ra_receiver(receiver_UID->Account.UID)，均 ON DELETE CASCADE

设计说明（一张表承载两类申请）：
- apply_type=1 好友申请：sender_UID 向 receiver_UID 申请，group_UID=0
- apply_type=2 群聊申请：sender_UID 申请加入 group_UID 群，receiver_UID=群主/管理员
- 唯一约束 uk_apply 防重复"等待中"记录：
      好友申请按 (1, A, B, 0, 0) 防同一对用户重复申请
      群聊申请按 (2, A, 群主, 群, 0) 防同一人重复申请同一群
- status 语义：0=等待；1=同意(处理完删除)；2=拒绝(处理完删除)
- 群聊申请流程：send_join_group 落申请(status=0) → handle_join_request 处理
  （同意则更新状态并拉人入群，拒绝仅更新状态）
- 注意：改名/重建唯一约束时须先删外键再删索引（旧索引被外键复用，
  直接 DROP INDEX 会报 ERROR 1553: needed in a foreign key constraint）

4. Group 表（群组）
------------------------------------------------------------
| 字段        | 类型             | 说明                         |
| group_UID   | bigint unsigned | 主键，系统自增分配             |
| name        | varchar(64)     | 群名称                       |
| owner_UID   | bigint unsigned | 创建者/群主(管理员)            |
| create_time | datetime        | 默认 CURRENT_TIMESTAMP       |
------------------------------------------------------------
主键 group_UID
外键：fk_group_owner(owner_UID->Account.UID)，ON DELETE CASCADE

说明：
- 群人数不单独存列：load_group 时用 SELECT COUNT(*) FROM Groupmember WHERE group_UID=? 统计，
  展示聊天列表时格式为 群名(人数):群UID（对应 group::member_count_，仅展示用）

============================================================
5. Groupmember 表（群成员）
------------------------------------------------------------
| 字段        | 类型             | 说明                         |
| group_UID   | bigint unsigned | 所属群（主键1）               |
| member_UID  | bigint unsigned | 成员（主键2）                 |
| name        | varchar(64)     | 群内名字(群名片)，默认取用户昵称 |
| role        | enum            | 'owner'群主 / 'member'普通   |
| join_time   | datetime        | 默认 CURRENT_TIMESTAMP       |
------------------------------------------------------------
联合主键 (group_UID, member_UID)
外键：fk_gm_group(group_UID->Group.group_UID)，
      fk_gm_member(member_UID->Account.UID)，均 ON DELETE CASCADE

说明：
- 联合主键 (group_UID, member_UID)，一个用户可加入多个群
- name 为成员在群内的名字（群名片）：入群时由 repo 层 JOIN Account
  默认填入用户昵称（见 repo/group_repo.cpp），之后可单独修改，不影响全局昵称
- role：'owner'=群主(创建者) / 'member'=普通成员（支持后续扩展 'admin'）

============================================================
6. message 表（聊天记录）
------------------------------------------------------------
| 字段          | 类型             | 说明                          |
| id            | bigint unsigned | 自增主键(保持发送顺序)          |
| type          | tinyint         | 1=私聊 2=群聊                 |
| sender_UID    | bigint unsigned | 发送者                        |
| receiver_UID  | bigint unsigned | 接收方(私聊=对方UID;群聊=group_UID)|
| content       | text            | 消息内容                      |
| send_time     | datetime        | 默认 CURRENT_TIMESTAMP       |
------------------------------------------------------------
主键 id
索引：
  idx_private(sender_UID, receiver_UID, id)  私聊会话查询
  idx_group(receiver_UID, id)                群聊历史
  idx_sender(sender_UID)
外键：无（本版为提升并发写入性能暂不强制外键，由应用层保证引用完整性）

设计要点：
- 私聊只写一条 (sender, receiver)，查询两人会话：
      WHERE ((sender=:me AND receiver=:other) OR (sender=:other AND receiver=:me))
- 群聊写一条 (sender, receiver=group_UID)
- 离线消息：按 send_time 查询（send_time > 用户上次登录时间），私聊 receiver=本人，
      群聊 receiver 在本人已加入的群中；由应用层 get_offline_messages 实现
- 删除消息：仅发送者本人、发送后 3 分钟内可删（应用层校验，非 DB 约束）；
      删除超时清理（超过 7 天）已实现 delete_expired_messages 但暂未接入
- 注：按需求"补消息不补文件"，未做文件表

============================================================
UID 分配与重启重定位（重要）
------------------------------------------------------------
现 C++ 侧用内存单例 UID_allocator 自增分配 UID/group_id。
引入 MySQL 后：
【彻底弃用内存分配器】
  插入前直接让 DB 生成 AUTO_INCREMENT 主键，再经 LAST_INSERT_ID() 取回。
  每注册/建群一次 DB round trip。
============================================================
关于"用户 UID 与群 group_UID 共用同一套编号空间"
------------------------------------------------------------
这是【有意为之、无歧义】的设计：request_uid() 与 request_group_id()
是两个独立计数器，某个用户 UID 与某个群 group_UID 数值可能相同(撞号)。
但每条消息都带 type 字段(private_chat/group_chat)，分发器 Chat_handler
先按 type 路由到 session.private_chat() / session.group_chat()，两者内部
各自只查 account_manager / Group_manager，两个查找空间天然隔离，
因此撞号不会造成转发歧义；持久化时同样靠 message.type 区分，安全。

============================================================
数据库连接接入（连接池，与代码衔接）
------------------------------------------------------------
服务器通过 db/mysql 连接池（MySQL_Conn_Pool，单例）访问数据库：
- 启动时（main.cpp）读 configure.json 的 database 配置并 init() 预建连接：
      host / port / user / password / dbname / db_conn_count(连接池上限，默认 4)
- get_connection() 取连接（达上限时阻塞等待归还），return_connection() 归还。
- 连接信息默认值（未读到配置文件时）：
      host=localhost  port=3306  user=chat_server  password=Chat_123!
      dbname=chat_server  db_conn_count=4
  （本仓库 DB 专用账户即上述 chat_server / Chat_123!）

注意：配置文件 configure.json 为相对路径，须复制到运行目录（build/）才能生效，
否则会使用上述默认值（可能连不上你本地的库或连到你预期的库）。
