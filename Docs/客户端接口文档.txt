客户端接口文档
================

一、通讯基础说明
----------------
*   **传输协议**：启动时二选一，两种模式都监听 IPv6 通配地址，端口 `8080`：
    *   `binary`：TCP + 自定义二进制帧。
    *   `websocket`：WebSocket，连接地址 `ws://<host>:8080/ws`。
*   **数据编码**：消息体统一使用 **protobuf**（`chat_proto.Envelope`，定义见 `src/proto/message.proto`），不再使用 JSON。
*   **关键特点**：
    1.  **支持粘包/半包处理**（仅 binary 模式）：服务器采用「4 字节总长度 + 4 字节 payload 长度」的定长包头分包。客户端发送时**无需**添加换行符 `\n`，但必须正确填写帧头长度字段。WebSocket 自带消息边界，无需 total_len。
    2.  **基于 UID 寻址**：所有用户（个人）、群组、社区、频道均以整数 ID 作为唯一标识。登录、私聊、群聊、频道发言等操作均使用 ID，而非用户名。
    3.  **服务器主动推送**：服务器可随时主动推送消息（如对方私聊、系统通知），客户端应**开启独立的接收线程**循环读取并解析。

二、帧格式
------------------------
### 2.1 binary（TCP）模式
所有通信数据均封装为如下帧结构：
```
┌──────────────┬──────────────┬──────────────────┬─────────────────┐
│  4 字节       │  4 字节       │ protobuf 字节     │ 文件数据(可选)   │
│  总长度 total │ payload 长度  │ (Envelope/FileMeta)│  (file_data)   │
└──────────────┴──────────────┴──────────────────┴─────────────────┘
```
*   **总长度 (total_len)**：`uint32_t`，网络字节序（大端）。其值 = `8 + payload 字节数 + 文件数据字节数`。
*   **payload 长度 (payload_len)**：`uint32_t`，网络字节序。其值 = protobuf 消息的字节数。
*   **payload 部分**：紧跟在两个 4 字节长度字段之后，长度为 `payload_len`，是 `chat_proto.Envelope`。
*   **文件数据部分**：紧跟在 payload 之后，长度为 `total_len - 8 - payload_len`，可缺省（长度为 0）。

> 服务器解析时，先读取前 4 字节得到 `total_len`，若接收缓冲区不足 `total_len` 则等待更多数据（半包）；处理完当前帧后继续循环处理剩余数据（粘包）。

### 2.2 WebSocket 模式
*   业务消息：**binary 帧**，payload 为 `4 字节 payload_len（大端） + protobuf Envelope`。
*   文件消息：同样为 binary 帧，`4 字节 payload_len + protobuf Envelope + file_data`。
*   text 帧不再用于业务消息；收到 text 帧会被当作旧 JSON 客户端，服务端回复 system 提示后继续读取。

三、消息类型总览
----------------
每个 `Envelope` 必须设置 `type` 字段（字段 1，string），用于指示消息类型。以下是全部受支持的类型：

| type                  | 归类     | 说明                                   |
|-----------------------|----------|----------------------------------------|
| `register`            | 基础     | 注册新账号                             |
| `login`               | 基础     | 用户登录（UID 或邮箱）                 |
| `logout`              | 基础     | 登出当前账号（保留连接，可再登录）     |
| `exit`                | 基础     | 退出系统、关闭连接                     |
| `show`                | 基础     | 展示聊天对象列表（文本）               |
| `show_contacts`       | 基础     | 结构化联系人列表（好友+群，含头像ID）  |
| `change_name`         | 基础     | 修改自己的昵称                         |
| `set_email`           | 基础     | 绑定/换绑当前账号邮箱                  |
| `set_avatar`          | 基础     | 设置自己的头像（指向已上传文件）       |
| `change_theme`        | 基础     | 修改主题（存 Account.settings JSON）   |
| `verify_token`        | 基础     | 用 token 自动登录                      |
| `heartbeat`           | 基础     | 心跳包（无业务消息时的保活）           |
| `private_chat`        | 私聊     | 私聊（一对一；可为文件消息）           |
| `group_chat`          | 群聊     | 群聊发言（可为文件消息）               |
| `delete_message`      | 消息     | 删除消息（仅发送者本人、3 分钟内）     |
| `history_request`     | 消息     | 按 message_id 游标分页拉聊天历史       |
| `add_friend`          | 好友     | 发送好友申请（按邮箱）                 |
| `set_friend_remark`   | 好友     | 给好友设置备注名                       |
| `accept_friend`       | 好友     | 同意好友申请                           |
| `reject_friend`       | 好友     | 拒绝好友申请                           |
| `remove_friend`       | 好友     | 删除好友                               |
| `show_friend_requests`| 好友     | 查看待处理的好友申请                   |

| `delete_group`        | 群组     | 解散群聊                               |

| `group_delete_client` | 群组     | 移除群成员（踢人）                     |

| `send_join_group`     | 群组     | 申请加入群聊                           |
| `handle_join_request` | 群组     | 处理入群申请（同意/拒绝）              |
| `modify_member_role`  | 群组     | 修改群成员身份（提升/降级）            |
| `show_group_members`  | 群组     | 查看群成员（含群内名字）               |
| `show_group_requests` | 群组     | 查看群聊待处理的入群申请（仅群主）     |
| `create_community`    | 社区     | 创建社区（自动建核心频道+创建者 owner）|
| `delete_community`    | 社区     | 删除社区（级联删频道/成员）            |
| `modify_community`    | 社区     | 修改社区资料（名称/简介/头像/背景图）  |
| `show_communities`    | 社区     | 查看我加入的社区列表（结构化）         |

| `delete_channel`      | 社区     | 删除频道                               |
| `modify_channel`      | 社区     | 修改频道（名称/分区）                  |

> 已移除旧的 `upload_file` / `download_file` 两个 type，请使用 `file_*` 系列。

四、Envelope 字段总表
--------------------------------------
`chat_proto.Envelope` 采用「大信封」设计，一个 message 承载所有请求/响应字段。客户端只需设置与当前 `type` 相关的字段，其余字段可留默认值（protobuf3 缺省：int=0、string=""、bool=false、message 不设置）。

| 字段名               | 字段号 | protobuf 类型 | 说明                                   |
|----------------------|--------|---------------|----------------------------------------|
| `type`               | 1      | string        | 消息类型，必填                         |
| `content`            | 2      | string        | 纯文本内容（system 消息/聊天正文）     |
| `target_UID`         | 3      | int32         | 私聊/群聊/频道目标 UID                 |
| `message`            | 4      | string        | 聊天消息正文                           |
| `message_id`         | 5      | int32         | 数据库消息 ID                          |
| `peer_id`            | 6      | int32         | 历史查询对象 UID/群 UID                |
| `before_id`          | 7      | int32         | 历史查询游标（0 取最新一页）           |
| `has_more`           | 8      | bool          | 历史是否还有更旧记录                   |
| `group_UID`          | 9      | int32         | 群 UID                                 |
| `target_user_UID`    | 10     | int32         | 被添加/移除的成员 UID                  |
| `requester_UID`      | 11     | int32         | 入群/入社区申请人 UID                  |
| `group_name`         | 12     | string        | 群名称                                 |
| `new_name`           | 13     | string        | 新群名/新昵称                          |
| `promote`            | 14     | bool          | 提升/降级                              |
| `friend_UID`         | 15     | int32         | 好友 UID                               |
| `sender_UID`         | 16     | int32         | 发送者 UID                             |
| `email`              | 17     | string        | 邮箱                                   |
| `apply_message`      | 18     | string        | 好友申请留言                           |
| `remark`             | 19     | string        | 好友备注名                             |
| `accept`             | 20     | bool          | 同意/拒绝                              |
| `UID`                | 21     | int32         | 登录 UID                               |
| `username`           | 22     | string        | 注册用户名                             |
| `password`           | 23     | string        | 密码                                   |
| `token`              | 24     | string        | 登录令牌（login_success 返回）         |
| `user`               | 25     | UserInfo      | 登录成功返回的用户信息                 |
| `sender_name`        | 26     | string        | 发送者昵称                             |
| `timestamp`          | 27     | string        | 发送时间 `YYYY-MM-DD HH:MM:SS`         |
| `reply_to_message_id`| 28     | int32         | 被回复消息 ID                          |
| `reply_to`           | 29     | ReplyTo       | 被回复消息摘要                         |
| `file_name`          | 30     | string        | 文件名（文件消息）                     |
| `meta`               | 31     | FileChunkMeta | 文件分块元信息（file_chunk）           |
| `messages`           | 32     | repeated ChatItem | 历史分页消息列表                  |
| `community_id`       | 33     | int32         | 社区 ID（=核心频道 id）                |
| `channel_id`         | 34     | int32         | 频道 ID                                |
| `category`           | 35     | string        | 频道分区                               |
| `description`        | 36     | string        | 社区简介                               |
| `avatar`             | 37     | string        | 社区头像 file_id 字符串（旧字段保留）  |
| `role`               | 38     | string        | 成员角色 owner/admin/member            |
| `is_channel`         | 39     | bool          | history_request 时标记频道历史         |

| `file_id`            | 47     | string        | 文件 ID（string 化的 file.id）         |

| `community_banner_id`| 54     | int32         | 社区背景图 file.id（modify_community） |
| `chunk_index`        | 55     | int32         | 下载分片块号（file_download_chunk）    |

### 子消息定义
```proto
message UserInfo {
  int32  id       = 1;  // 用户 UID
  string username = 2;  // 昵称
}

message ReplyTo {
  int32  message_id  = 1;
  string sender_name = 2;
  string content     = 3;
}

message ChatItem {
  int32  message_id          = 1;
  int32  sender_UID          = 2;
  string sender_name         = 3;
  bool   is_group            = 4;
  string content             = 5;
  string timestamp           = 6;
  int32  reply_to_message_id = 7;
  ReplyTo reply_to           = 8;
  bool   is_file             = 9;   // 文件消息
  int32  file_id             = 10;  // file.id
  string file_name           = 11;  // 原始文件名
  uint64 file_size           = 12;  // 文件大小
}

message FileChunkMeta {
  string type        = 1;  // 恒为 "file_chunk"
  string file_id     = 2;
  string filename    = 3;
  uint64 total_size  = 4;
  uint32 chunk_index = 5;
  uint32 chunk_count = 6;
  uint32 chunk_size  = 7;
  uint64 offset      = 8;
  string transfer_id = 9;  // 传输会话 ID
  string hash        = 10; // 首块可选携带全文件 sha256
}

message FileMeta {
  string file_id       = 1;  // string 化的 file.id
  string original_name = 2;
  string mime_type     = 3;
  uint64 size          = 4;
  string hash          = 5;  // sha256
  string type          = 6;  // avatar/emoji/image/attachment/file
  int32  uploader_uid  = 7;
  string created_at    = 8;
}

message FileTransferInfo {
  string transfer_id      = 1;
  string file_id          = 2;
  int32  uploader_uid     = 3;
  int32  receiver_uid     = 4;
  string direction        = 5;  // upload / download
  string status           = 6;  // uploading/downloading/paused/completed/cancelled/failed
  uint64 total_size       = 7;
  uint64 transferred_size = 8;
  uint32 chunk_size       = 9;
  uint32 chunk_count      = 10;
  uint32 next_chunk_index = 11;
}

message CommunityInfo {
  int32  community_id = 1;
  string name         = 2;
  string description  = 3;
  string avatar       = 4;  // 旧字段，字符串 file_id
  string category     = 5;
  string my_role      = 6;  // owner/admin/member
  int32  avatar_id    = 7;  // 社区头像 file.id
  int32  banner_id    = 8;  // 社区背景图 file.id
}

message ChannelInfo {
  int32  channel_id   = 1;
  int32  community_id = 2;
  string name         = 3;
  string category     = 4;
}

message MemberInfo {
  int32  user_uid  = 1;
  string nickname  = 2;
  string role      = 3;
  int32  avatar_id = 4;  // 成员头像 file.id
}

message ContactInfo {
  int32  uid       = 1;
  string name      = 2;
  bool   is_group  = 3;
  int32  avatar_id = 4;  // 好友头像 file.id；群为 0
}
```

五、客户端请求接口（Client -> Server）
--------------------------------------
以下所有请求都封装为 `Envelope`，需设置 `type` 与对应字段。

### 1. 注册账号 (register)
*   **用途**：创建新账号，服务器自动分配 UID。**新用户必须填邮箱**（不校验格式，仅要求不重复）。
*   **字段**：`type="register"`、`username`、`password`、`email`
*   *注意*：注册成功后服务器回传 system 文本，例如
    `Registration successful. You can now log in with UID 000001 or zhangsan@example.com.`
    邮箱已被占用时返回 `Email [xxx] is already registered.`

### 2. 用户登录 (login)
*   **用途**：用 **UID** 或 **邮箱** + 密码登录。
*   **字段（用 UID）**：`type="login"`、`UID`、`password`
*   **字段（用邮箱）**：`type="login"`、`email`、`password`
*   *注意*：`email` 非空时按邮箱登录，否则按 `UID` 登录。
*   **成功响应**：`type="login_success"`，携带 `token`、`user{id, username}`、`avatar_id`（当前头像 file.id，-1 表示未设置）、
    `email`（已绑定邮箱时返回，未绑定则为空字符串）。
    邮箱未绑定时返回 system `No account is bound to email [xxx].`

### 2.1 用 token 自动登录 (verify_token)
*   **字段**：`type="verify_token"`、`token`
*   *注意*：token 有效（7 天滑动过期）则返回 `login_success`，否则返回 system 提示。

### 3. 展示聊天列表 (show)
*   **字段**：`type="show"`
*   **返回**：`system` 类型文本，格式见 §七。

### 3.1 结构化联系人列表 (show_contacts)
*   **字段**：`type="show_contacts"`
*   **响应**：`type="contact_list_response"`，携带 `contacts`（repeated ContactInfo），
    每个好友带 `uid/name/is_group=false/avatar_id`，每个群带 `uid/name/is_group=true/avatar_id=0`。
*   *推荐*：需要好友头像时优先用本接口，替代文本 `show`。

### 4. 私聊 (private_chat)
*   **字段**：`type="private_chat"`、`target_UID`、`message`；`reply_to_message_id` 可选。
*   **文件消息**：额外设置 `is_file=true`、`file_id`（string，已上传文件的 file.id）；`message` 可为空。
*   *注意*：对方在线时实时转发；离线时落库，上线后补发。转发的消息携带
    `message_id`、`sender_UID`、`sender_name`、`timestamp`；文件消息还带
    `is_file/file_id/file_name/file_size`；回复消息还带 `reply_to_message_id` 与 `reply_to`。
    发送者收到 system `Message sent. Message ID: <id>.`

### 5. 群聊 (group_chat)
*   **字段**：`type="group_chat"`、`target_UID`（群 UID）、`message`；`reply_to_message_id` 可选。
*   **文件消息**：同私聊，额外 `is_file=true`、`file_id`。
*   *注意*：转发的 `Group_Chat` 消息携带 `message_id`、`group_UID`、`sender_UID`、`sender_name`、`timestamp`。

### 6. 创建群聊 (create_group)
*   **字段**：`type="create_group"`、`group_name`

### 7. 解散群聊 (delete_group)
*   **字段**：`type="delete_group"`、`group_UID`

### 8. 添加群成员 (group_add_client)
*   **字段**：`type="group_add_client"`、`group_UID`、`target_user_UID`

### 9. 移除群成员 (group_delete_client)
*   **字段**：`type="group_delete_client"`、`group_UID`、`target_user_UID`

### 10. 修改群名称 (modify_group_name)
*   **字段**：`type="modify_group_name"`、`group_UID`、`new_name`

### 11. 上传文件 (file_upload_init / file_chunk / file_upload_done)
*   **用途**：分片上传文件，支持顺序/乱序、暂停/续传、断线重传。
*   **第一步 `file_upload_init`**：`type="file_upload_init"`、`file_meta{original_name,size,mime_type,type,hash(可选)}`；
    可选 `target_UID`（指定接收方，可空）。服务端回 `file_upload_ready`（`transfer_info{transfer_id,chunk_size,chunk_count}`）。
*   **第二步 `file_chunk`**：`type="file_chunk"`、`meta{transfer_id,chunk_index,offset,chunk_size,...}`，
    文件二进制放帧尾 `file_data`。可乱序发块。
*   **第三步 `file_upload_done`**：`type="file_upload_done"`、`transfer_id`。
    服务端校验分片齐全 + sha256 后回 `file_upload_complete`（`file_meta{file_id,...}`）。
*   *注意*：分片大小默认 4 MiB（由 `file_storage.chunk_size` 决定）；服务端有单文件/头像大小上限。

### 12. 下载文件 (file_download_init / file_download_chunk)
*   **用途**：拉取式分片下载（客户端逐块拉取，天然背压，可暂停）。
*   **第一步 `file_download_init`**：`type="file_download_init"`、`file_id`（string）。
    服务端回 `file_download_ready`（`file_meta` + `transfer_info{transfer_id,chunk_count,chunk_size}`）。
*   **第二步 `file_download_chunk`**：`type="file_download_chunk"`、`transfer_id`、`chunk_index`。
    服务端回 `file_chunk`（`meta{transfer_id,chunk_index,offset,chunk_size,...}` + 帧尾 `file_data`）。
*   *注意*：客户端按 `chunk_index` 从 0 逐块拉取，直到最后一块；最后一块拉完后会话置 completed。

### 12.1 断线重续上传 (file_upload_resume)
*   **用途**：上传中断线后重连续传。
*   **字段**：`type="file_upload_resume"`、`transfer_id`
*   *注意*：服务端从 DB 恢复上传会话，回 `file_upload_ready`（含 `next_chunk_index`），
    客户端从 `next_chunk_index` 继续发 `file_chunk`，最后 `file_upload_done`。

### 12.2 暂停 / 继续 / 取消 / 进度
*   `file_transfer_pause`：`transfer_id` → 回 `file_transfer_paused`。
*   `file_transfer_resume`：`transfer_id` → 回 `file_transfer_progress`。
*   `file_transfer_cancel`：`transfer_id` → 回 `file_transfer_progress`。
*   `file_transfer_status`：`transfer_id` → 回 `file_transfer_progress`。
*   *注意*：下载暂停 = 客户端停止发 `file_download_chunk`。

### 12.3 文件列表 / 删除
*   `file_list_request`：可选 `before_id` 分页 → 回 `file_list_response`（`files[]`）。
*   `file_delete`：`file_id` → 删除文件，回 system `File deleted.`

六、服务器返回格式（Server -> Client）
--------------------------------------
| 响应类型 (type)       | 场景/含义                                            | 携带字段说明                                            |
|-----------------------|------------------------------------------------------|--------------------------------------------------------|
| `system`              | 通用系统提示、错误提示、show 列表等                  | `content` 为纯文本                                     |
| `login_success`       | 登录成功                                             | `token`、`user{id, username}`、`avatar_id`             |
| `private_chat`        | 收到私聊消息                                         | `content`、`message_id`、`sender_UID`、`sender_name`、`timestamp`；文件消息还带 `is_file/file_id/file_name/file_size`；回复还带 `reply_to_message_id/reply_to` |
| `Group_Chat`          | 收到群聊消息                                         | 同私聊，另带 `group_UID`                               |
| `Channel_Chat`        | 收到频道消息                                         | 同私聊，另带 `group_UID`（=频道 id）                  |
| `history_response`    | 聊天历史分页响应                                     | `peer_id`、`messages[]`、`has_more`                    |
| `delete_message`      | 消息被删除通知                                       | `content` 为空，`message_id`；群聊/频道还带 `group_UID` |
| `file_upload_ready`   | 同意上传                                             | `transfer_info`                                        |
| `file_upload_complete`| 上传完成                                             | `file_meta{file_id,...}`、`transfer_info`              |
| `file_download_ready` | 下载就绪                                             | `file_meta`、`transfer_info`                           |
| `file_chunk`          | 文件分片（上传回执/下载数据）                         | `meta`（FileChunkMeta），文件数据在帧尾                |
| `file_transfer_paused`| 已暂停                                               | `transfer_info`                                        |
| `file_transfer_progress` | 进度响应/取消响应                                  | `transfer_info`                                        |
| `file_list_response`  | 文件列表                                             | `files[]`（repeated FileMeta）                         |
| `contact_list_response` | 结构化联系人列表                                   | `contacts[]`（repeated ContactInfo）                   |
| `community_list_response` | 社区列表响应                                    | `communities[]`（含 avatar_id/banner_id）              |
| `channel_list_response`   | 频道列表响应                                    | `channels[]`                                           |
| `community_member_list_response` | 社区成员列表响应                         | `members[]`（含 avatar_id）                            |
| `heartbeat_ack`       | 心跳应答                                             | `content`=`pong`                                       |

> `private_chat` / `Group_Chat` / `Channel_Chat`（含离线推送）的 `content` 为**原始内容**；
> `message_id` 可用于 `delete_message`；文件消息额外带 `file_id`（string）+ `file_name` + `file_size`；
> 回复消息额外带 `reply_to`（`{message_id, sender_name, content}`），只展示一层引用。

七、聊天列表返回格式
----------------------------
### 7.1 文本列表（show）
`show` 请求返回 `system` 类型、`content` 纯文本。格式为**每行一条记录**：
*   好友记录：`<用户名>:<6位补齐的UID>`，例如 `张三:001001`；若设置备注名则显示备注名。
*   群组记录：`<群名>(人数):<6位补齐的UID>`，例如 `我的新群聊(3):002001`。

示例：
```
张三:001001
李四:001002
我的新群聊(3):002001
```

### 7.2 结构化列表（show_contacts）
`show_contacts` 返回 `contact_list_response`，`contacts[]` 为 `ContactInfo`，
含 `uid / name / is_group / avatar_id`。推荐需要头像的客户端使用本接口。

八、完整交互流程示例
--------------------
1.  **建立连接**：binary 模式连接 `:8080`；WebSocket 模式连接 `ws://<host>:8080/ws`。
2.  **登录**：发送 `type="login"`、`UID`、`password`，收到 `login_success`（含 `avatar_id`）。
3.  **查询列表**：发送 `type="show_contacts"` 拿结构化联系人；或 `type="show"` 拿文本列表。
4.  **私聊**：发送 `type="private_chat"`、`target_UID`、`message`。
5.  **发文件消息**：先 `file_upload_init/file_chunk/file_upload_done` 拿 `file_id`，
    再发 `private_chat/group_chat/channel_chat` 带 `is_file=true`、`file_id`。
6.  **下载文件**：`file_download_init(file_id)` → `file_download_chunk` 逐块拉取。
7.  **接收**：接收线程持续解析，按 `type` 分别处理 `private_chat` / `Group_Chat` / `file_chunk` / `system` 等。
8.  **退出**：发送 `type="exit"` 后断开连接。

九、客户端开发建议
------------------
1.  **独立接收线程**：服务器支持主动推送，客户端必须开启独立线程持续 `recv` 并解析帧。
2.  **严格遵循帧头（binary 模式）**：`total_len = 8 + payload字节数 + file字节数`、`payload_len`，大端写入前 8 字节。
3.  **登录状态控制**：收到 `login_success` 之前，除 `login`（必要时 `register`）外不要发其它业务请求。
4.  **UID 而非用户名**：所有寻址均使用整数 UID。
5.  **protobuf 生成**：用 `protoc` 从 `src/proto/message.proto` 生成客户端消息类，字段号以该文件为准。
6.  **文件分块**：上传/下载统一走 `file_*` 系列；分片大小以 `file_upload_ready`/`file_download_ready` 返回的
    `chunk_size` 为准（默认 4 MiB），客户端按 `chunk_index` 组装。
7.  **文件消息**：聊天消息里文件只是元数据引用（`file_id/file_name/file_size`），本体点击后 `file_download_init` 下载。

十、WebSocket 接入方式
-----------------------------------------------
服务端支持两种网络层，由 `configure.json` 的 `net_layer` 在启动时二选一，两种模式都监听 `8080`，同一时刻只启用一种：

*   `"net_layer": "binary"`：TCP + 二进制帧协议。
*   `"net_layer": "websocket"`：WebSocket，地址为 `ws://<host>:8080/ws`。

WebSocket 模式下的约定：
1.  **握手**：路径必须是 `/ws`（允许带 query）。错误路径返回 `404`，非 Upgrade 请求返回 `426`。
2.  **业务消息**：使用 **binary 帧**，payload = `4 字节 payload_len（大端） + protobuf Envelope`。
3.  **消息类型与返回**：与第三~七节的 type、字段、system 提示文本完全一致，只是载体从 TCP 帧换为 WS binary 帧。
4.  **心跳**：同样发送 `type="heartbeat"`，服务端回 `heartbeat_ack`。
5.  **text 帧**：不再使用；收到 text 帧服务端返回 system 提示后继续读取。
6.  **文件传输**：WebSocket 与 binary 一样支持 `file_*` 系列；`file_chunk` 的文件数据放 WS binary 帧尾部。
7.  **大小限制**：单条消息默认上限 8 MiB（`websocket.max_message_bytes`，需大于文件分片 4 MiB）；
    单连接待发送队列上限默认 8 MiB（`websocket.max_pending_bytes`）。

WebSocket 模式还内置静态前端服务：
*   浏览器直接打开 `http://<host>:8080/` 即可加载聊天页（`/` 映射到 `/index.html`）。
*   静态资源目录由 `websocket.web_root` 指定（默认 `./web`，相对运行目录；从 `build/` 运行时为 `../web`）。
*   只服务 GET/HEAD 与白名单扩展名，路径含 `..` 返回 400，未命中返回 404。

十一、附加：服务端部署与配置
-----------------------------------------------
*   服务端启动时读取**相对路径** `configure.json`，需先复制到运行目录（如 `cp configure.json build/`）。
*   `configure.json` 主要配置：
    1.  `net_layer`：`binary` 或 `websocket`。
    2.  心跳：`use_heartbeat`、`heartbeat_interval`。
    3.  WebSocket：`websocket.path/io_threads/max_message_bytes/max_pending_bytes/web_root`。
    4.  数据库连接池：`database.host/port/user/password/dbname/db_conn_count`。
    5.  文件存储：`file_storage.root/chunk_size/max_chunk_size/max_file_size/max_storage_size/max_avatar_size/transfer_timeout_seconds`。
*   未读到配置文件时使用默认值，可能导致无法连接数据库。
